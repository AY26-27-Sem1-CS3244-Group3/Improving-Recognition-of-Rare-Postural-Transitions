# Local LDA explainability

`evaluation.ipynb` section 7.7 uses these files. Run the report from the project
root or `our approach`. The section requires `lime==0.2.0.1`, scikit-learn,
SciPy and threadpoolctl in addition to the report's existing dependencies.

- `lda_fixed_parameters.npz`: numeric coefficients, intercepts, scaler means and
  scales, ordered feature/class names, the training reference, refit test
  probabilities and final labels, and JSON provenance. It contains no pickle.
- `analysis_summary.json`: the case selection, all six LIME diagnostic rows,
  exact score margins, package versions and source/data fingerprints.
- `build_parameters.py`: code to generate the parameter file with one fit of
  the already selected configuration. Training is disabled by default.

The original trained model and scaler were not archived. **One** fit of the
previously selected seven-window configuration was performed
for explainability: training-only StandardScaler, raw features, LDA with
`solver="lsqr"`, `shrinkage="auto"`, equal priors and the source posture-memory
rule. No cross-validation, search or retuning was performed. The source
notebooks were not edited. The refit's final labels match all 3,162 recorded
test predictions. This verifies the observed labels, not identity with the
original fitted object or its internal coefficients. Original result tables
remain unchanged.

The report loads the numeric parameters and regenerates probabilities by
applying the saved scaler, linear class scores and softmax. Float32 array
layout/BLAS can produce small probability differences, so it checks a numeric
tolerance and requires **exact** agreement for all final labels. Source and CSV
fingerprints normalize CRLF to LF. A changed snapshot stops this supplementary
analysis for review, including edits to Markdown, saved outputs or notebook
metadata in either source notebook. Review whether the parameters still apply
before updating their provenance; changing hashes alone does not validate them.
Subsequent report execution never fits LDA again; LIME
does fit its own explanatory surrogate regressions.

## Parameter-generation code

Run these commands from the repository root. The default command prints the
training-disabled status without fitting or writing files:

```powershell
python "our approach/explainability/build_parameters.py"
```

To intentionally reproduce the fit, choose a new output path:

```powershell
python "our approach/explainability/build_parameters.py" --fit --output "our approach/explainability/lda_rebuilt_parameters.npz"
```

The script uses the supplied training CSV to fit the scaler and seven-window
LDA, then applies the unchanged posture-memory rule to test probabilities.
The companion's saved labels are read as data; its training cells are not
executed. All final labels must match those records before anything is saved.
Existing outputs are never overwritten. The configuration, source/data hashes
and environment versions are stored in the new parameter file. The original
environment is recorded in `analysis_summary.json`; different numerical-library
versions may prevent exact reproduction. Runtime and provenance metadata need
not produce a byte-identical archive.

The report continues to load `lda_fixed_parameters.npz`. Review a rebuilt file
before adopting it under that name. Rerun section 7.7 to obtain explanations
for the reviewed parameters; `analysis_summary.json` describes the supplied
snapshot and is not automatically regenerated by the builder.

The two cases are selected by a stated rule before inspecting their LIME
rankings: the first correct STAND_TO_SIT window (row 16), and the first
LIE_TO_STAND-to-WALKING error (row 2874). Each uses 2,000 perturbations and ten
features for seeds 42, 123 and 2026. All runs are reported. The input has 3,927
standardized features, preserving the source's participant-bounded context.

LIME's local R² is approximately 0.010–0.015, and its top features vary across
seeds. These are low-fidelity exploratory fits, not reliable sensor attribution.
The plots therefore also show exact pairwise **linear-score** contributions
relative to the mean standardized training context. Their units differ from
probability contributions; the complete decomposition is checked, while the
plots label the contribution of omitted features. These examples explain the
refitted base LDA before memory and do not establish causal effects, global
importance, calibrated probabilities or online performance.

The source notebooks are identical between those two snapshots. Full source,
data and environment details are embedded in the parameter file and summary.
The numeric parameters avoid archiving the unnecessary large covariance matrix.
